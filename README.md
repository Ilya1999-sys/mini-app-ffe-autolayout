# Figa Trainer Quiz App

Telegram Mini App с тестом из семи вопросов по Auto Layout. Макет: [Figma](https://www.figma.com/design/KRhUglB3nBqRBtQ0YSTrLr/Gamification?node-id=3-172). Репозиторий: [GitHub](https://github.com/Ilya1999-sys/mini-app-ffe-autolayout), production: [Vercel](https://mini-app-ffe-autolayout.vercel.app/). Коммиты в `main` автоматически публикуются в production.

## Как работает выдача промокода

Пользователь проходит тест в Telegram и нажимает «Получить выгоду». Сервер проверяет подпись запуска Telegram, пересчитывает семь ответов, регистрирует вебхук бота (если он свободен или уже указывает на этот проект) и отправляет в бот четыре кнопки: курс для UX-редакторов, базовый курс по Фигме, курс для презентаций и консультации. При выборе бот читает [таблицу промокодов](https://docs.google.com/spreadsheets/d/1qkHoYUkzK5hXIJKjfxkeH3uCBJr2F5qgyyvzPQD6H94/edit?usp=sharing) и отправляет код из строки с набранными баллами и колонки выбранного продукта, процент скидки и ссылку на выбранный курс либо контакт [@ilya_uxui_design](https://t.me/ilya_uxui_design) для консультации. Изменения в ячейках применяются при следующем выборе продукта; повторный деплой не нужен.

## Одно прохождение на Telegram ID

Для постоянного ограничения подключите Upstash Redis к проекту Vercel и включите окружение **Production**. Интеграция должна добавить `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`; после этого выполните redeploy. Без этих двух переменных ограничение **не действует**, а тексты сообщений и выдача промокодов работают как прежде.

При подключённом Redis сервер атомарно сохраняет первый результат по Telegram ID без срока истечения. Повторная отправка теста отклоняется; повторный `/start` показывает сохранённый результат и кнопки продуктов вместо кнопки запуска. Mini App также проверяет статус при открытии и показывает экран завершения. Если отправка сообщения о результате временно не удалась, пользователь может отправить `/start` и получить кнопки по сохранённому результату. Результаты, полученные до подключения Redis, не записаны и автоматически не восстановятся.

Для группы тестирующих — `@ilya_uxui_design`, `@dm1017y`, `@Olya25112` — ограничение не применяется: они могут запускать тест повторно и каждый раз получать результат. Telegram username проверяется без учёта регистра по подписанным данным Mini App или сообщению вебхука. При смене username доступ к повторным попыткам по старому нику прекратится.

**Таблица сейчас содержит один код для каждой пары «баллы × продукт».** Этот код повторно получат все пользователи с тем же результатом и выбором. Если требуются индивидуальные одноразовые коды, нужна таблица с запасом кодов и хранилище для атомарного учёта выдачи. Общедоступную ссылку на таблицу следует считать доступом к самим промокодам.

## Подключение к @FigmaForEditors_bot

1. В проекте Vercel `mini-app-ffe-autolayout` добавьте переменную окружения `TELEGRAM_BOT_TOKEN` для **Production**. Значение — токен бота из `@BotFather`. Не сохраняйте его в Git и не отправляйте в переписке. После добавления переменной запустите Redeploy последнего production-деплоя или отправьте новый коммит.
2. В `@BotFather` → `/mybots` → `@FigmaForEditors_bot` → **Bot Settings** → **Menu Button** укажите URL `https://mini-app-ffe-autolayout.vercel.app/` и короткое название кнопки, например «Пройти тест».
3. Откройте Mini App через кнопку меню бота, пройдите тест и выберите один из четырёх продуктов. После первого результата вебхук настроится автоматически, а бот отправит код и кнопку ссылки на продукт. Если у бота есть вебхук на другом адресе, автоматическая настройка остановится и потребует проверки.

Для ручной проверки или установки вебхука задайте `TELEGRAM_BOT_TOKEN` в локальном терминале, не записывая его в файл или историю команд (например, в `zsh`: `read -rs "TELEGRAM_BOT_TOKEN?Токен: "; echo; export TELEGRAM_BOT_TOKEN`). Запустите `node scripts/setup-webhook.js`: команда покажет адрес текущего вебхука и проверит, что токен принадлежит `@FigmaForEditors_bot`. Если вебхука нет, установите его через `node scripts/setup-webhook.js --install`. Скрипт не заменит другой действующий вебхук автоматически. После настройки выполните `unset TELEGRAM_BOT_TOKEN`.

Если у бота уже есть код или вебхук, обработку `/start`, результатов теста и выбора продукта нужно объединить с действующим обработчиком перед переключением вебхука. Для запуска Mini App через **клавиатурную** Web App-кнопку используйте URL `https://mini-app-ffe-autolayout.vercel.app/?launch=keyboard`; в этом режиме бот получает `web_app_data`.

## Локальная проверка

Для статического интерфейса: `python3 -m http.server 4173`, затем `http://localhost:4173/`. API-функции работают в Vercel. Проверка логики: `node --test test/bot.test.js`.

Клиентский код теста доступен пользователю, поэтому пересчёт на сервере защищает от подмены только готового числа баллов, но не доказывает, что человек честно прошёл вопросы. Для скидок с существенной стоимостью понадобится серверная модель попыток и дополнительные ограничения.

## Опросы канала через бота

В `lib/channel-polls.js` подготовлены шесть опросов из `../analyse/05-polls-plan.md`: по вторникам с 13 октября по 17 ноября 2026 года. После первого опроса, вышедшего в 11:09 МСК, расписание с 20 октября выставлено на 07:00 UTC: на Vercel Hobby запуск возможен в интервале 10:00–10:59 МСК. `vercel.json` вызывает `/api/channel-polls-cron` каждый вторник. После 17 ноября обработчик возвращает `no_poll` и ничего не публикует.

Для работы планировщика нужны три условия в **Production**:

1. `@FigmaForEditors_bot` — администратор `@proeditor_figma` с правом **публиковать сообщения**. Другие права для опросов не нужны. Обработчик сам проверяет имя бота и право через Telegram Bot API перед отправкой.
2. Уже используемый `TELEGRAM_BOT_TOKEN` относится к `@FigmaForEditors_bot`. Токен остаётся в переменных Vercel; в Git и в сообщения его не помещать.
3. Заданы `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` и новый `CRON_SECRET`. Без Redis или секрета обработчик отказывает в отправке. `CRON_SECRET` должен быть случайной строкой в переменных Production; Vercel передаёт её cron-вызову в заголовке Authorization.

9 октября 2026 года production-деплой зарегистрировал cron `25 7 * * 2`; 13 октября расписание изменено на `0 7 * * 2`, чтобы будущие опросы выходили с 10 до 11 МСК. Проверочный запуск до первой даты вернул HTTP 200 после проверки имени бота, прав публикации и ответа Redis; опрос не публиковался. Локальные тесты: `node --test test/channel-polls.test.js test/bot.test.js`. При каждом запуске в назначенную дату обработчик сначала отмечает дату в Redis, а затем отправляет один анонимный опрос с одним ответом и автоматическим закрытием через шесть дней. Повторный вызов не отправляет дубль. Если Telegram вернул ошибку или ответ потерялся, **сначала проверьте канал и ключ `ffe:channel-poll:v1:YYYY-MM-DD`**, затем решайте вопрос о ручной отправке: автоматического повтора нет, чтобы не получить два одинаковых опроса.

На Vercel Hobby расписание `07:00 UTC` не обеспечивает точность до минуты, но даёт окно 10:00–10:59 МСК. Для публикации именно в 10:25 МСК нужен Vercel Pro либо другой точный планировщик. Сам Telegram Bot API отправляет опрос в момент вызова и не создаёт запись во встроенной очереди отложенных сообщений канала.
